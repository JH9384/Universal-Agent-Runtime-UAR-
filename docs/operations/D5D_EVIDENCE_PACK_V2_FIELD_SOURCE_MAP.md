# D5D Evidence Pack v2 Field Source Map

## Status

D5D maps Evidence Pack v2 fields to existing UAR sources.

## Purpose

Prepare Evidence Pack v2 for implementation without inventing data or creating duplicate runtime surfaces.

## Source Documents

- `docs/operations/D5B_OPERATOR_EVIDENCE_PATH.md`
- `docs/operations/D5C_EVIDENCE_PACK_V2_SHAPE.md`

## Source Rule

Every Evidence Pack v2 field must be one of:

1. sourced from an existing endpoint/module,
2. derived from existing data, or
3. explicitly marked unavailable.

No silent empty fields.

## Implementation Slices

### Slice 1 — Read-Only Pack Builder

Build a read-only pack generator that accepts:

- `run_id`
- optional `signal_id`
- optional `recommendation_id`
- optional `outcome_id`

It should gather existing data and mark unavailable fields explicitly.

### Slice 2 — Markdown Export

Generate a human-readable markdown evidence pack before JSON/API expansion.

### Slice 3 — JSON Export

Generate stable JSON using the D5C skeleton.

### Slice 4 — API Endpoint

Add an authenticated endpoint only after the builder is stable.

Potential path:

```text
GET /api/uar/evidence-pack/{run_id}
```

## Guardrails

- Pack generation must be read-only.
- Missing data must be explicit.
- Do not create duplicate Mission Control or replay surfaces.
- Do not mutate outcomes during pack generation.
- Do not weaken D4G warning gates.
